# Zoho integration status for Office

**Scope:** compare the requested Mail, free Campaigns, and optional prepaid Email API features with the code currently wired into Office. This is a source inspection, not a live-account verification. Mock-provider coverage does not prove a Zoho account or plan has been connected successfully. See the [capability matrix](./zoho-api-capability-matrix.md) for official Zoho API contracts.

Status meanings: **Wired** means an application/API or UI path calls the provider; **SDK-only** means provider code exists but no application caller or route uses it; **Not implemented** means no relevant provider operation/path was found.

## Main blockers before any Zoho marketing send

1. **Production marketing delivery is disabled.** API and worker use `DisabledDeliveryProvider` outside the explicit dev/test fake configuration. Zoho Campaigns and Email API are not registered as production marketing delivery providers. [API provider selection](../../crates/api/src/state.rs#L41) · [worker provider selection](../../crates/worker/src/lib.rs#L47) · [disabled delivery](../../crates/api/src/state.rs#L144)
2. **Campaigns OAuth is read-only.** The current consent scope list cannot authorize contact writes, Campaigns creation/update, unsubscribe suppression, or sending. Those SDK operations still have no application contract/UI. A Campaigns Free path needs narrower write scopes and an explicit Office-to-Campaigns integration for consent, contacts, native unsubscribe mapping, campaign draft/review/send, and polling reports.
3. **Email API is not a drop-in path for the current Campaigns organization.** It is a separate prepaid product/org choice. Although template CRUD is wired, current inline-send code is single-recipient and does not carry the supported merge data/template ID or implement native unsubscribe/suppression synchronization. Its API-client `send` capability does not make it a usable marketing sender in Office.
4. **Zoho-native opt-out is not connected.** Office’s local unsubscribe endpoint records Office suppression, but no adapter currently forwards it to Campaigns or Email API. Campaigns’ required provider-native unsubscribe tag is not inserted into imported HTML, and Email API’s marker/webhook handling is not implemented. Until that work exists, do not treat either Zoho route as a compliant send path.
5. **Do not use Zoho Mail for campaigns.** The integrated Mail provider intentionally restricts outbound Mail to correspondence. A paid Mail subscription does not grant Campaigns API write scopes or Email API access.

Contact write encoding and recipient-report paging still require live-account contract verification: the official contact example is not valid standard JSON, and report paging inputs are not documented. A subscription acceptance response does not establish confirmed consent. These SDK methods remain unreachable from marketing application routes.

These paths have local mock/test coverage, but this status review made no live Zoho API calls and did not verify the user’s account, credentials, plan, sender/domain, templates, or send quotas.

No Zoho workflows, automatic sequences, or scheduled-send operations are wired. The current Office launch guard rejects legacy revisions containing multiple or delayed steps. [Launch guard](../../crates/application/src/campaigns/launch.rs#L118)

## Credentials and operator setup

Credentials belong in the API/worker runtime environment, never the browser or this document. Production configuration also requires `OUTREACH_SECRET_KEY` for OAuth token storage and `OUTREACH_HMAC_KEY`; the callback must be HTTPS and exactly registered in Zoho. Zoho binaries do not load `.env` automatically. [Environment names](../../.env.example#L47) · [config parsing](../../crates/infrastructure/src/config.rs#L90)

| Choice | Required server configuration | Zoho-side setup / limitation |
|---|---|---|
| Use the existing Zoho Mail account | `ZOHO_MAIL_CLIENT_ID`, `ZOHO_MAIL_CLIENT_SECRET`, `ZOHO_MAIL_REDIRECT_URI` (or the configured public-origin default, `${PUBLIC_BASE_URL}/api/v1/integrations/zoho/callback`), `OUTREACH_SECRET_KEY`; the API and worker need the Mail configuration. | Register a Server-based OAuth client, register the exact Mail callback, and approve the scopes Office requests: `ZohoMail.messages.READ`, `ZohoMail.messages.CREATE`, `ZohoMail.accounts.READ`, `ZohoMail.folders.READ`. This path is for ordinary correspondence only. [Scopes](../../crates/domain/src/mailboxes.rs#L92) |
| Stay on the existing Campaigns Free account | `ZOHO_CAMPAIGNS_CLIENT_ID`, `ZOHO_CAMPAIGNS_CLIENT_SECRET`, `ZOHO_CAMPAIGNS_REDIRECT_URI` (defaults to `${PUBLIC_BASE_URL}/api/v1/integrations/zoho-campaigns/callback`), `OUTREACH_SECRET_KEY`. | Register a Server-based OAuth client and exact callback in Zoho; current code supports the US `.com` data center and asks only for Campaigns/contact READ. Enabling the requested marketing operations requires implementation and renewed consent for additional scopes. [Environment sample](../../.env.example#L47) |
| Choose Zoho Campaigns Email API v2 | `ZOHO_EMAIL_API_ENABLED=true`, `ZOHO_EMAIL_API_KEY`, `ZOHO_EMAIL_API_WORKSPACE_ID`; key is server-side and must match the configured workspace. | Zoho must enable Email API for the separate organization and prepaid credits must be available. The API key scope is broad (`ZohoCampaigns.emailapi.ALL`). The existing Campaigns Free organization cannot also be used as the Email API organization. [Email API settings](../../crates/infrastructure/src/providers/zoho_campaigns/mod.rs#L112) · [workspace gate](../../crates/application/src/marketing/email_templates.rs#L47) |
