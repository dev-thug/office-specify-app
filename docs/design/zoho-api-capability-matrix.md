# Zoho API capability matrix for Office

**Purpose:** document provider capabilities available for Office integration, not what this repository has implemented. Checked against Zoho’s official documentation on 2026-10-10. The account context is Zoho Mail paid plus `campaigns.zoho.com` Forever Free. Plan entitlements and API contracts are separate.

## Decision boundary

There are three distinct products in these docs:

1. **Zoho Mail REST API** is for an authenticated mailbox: reading/responding to ordinary business mail, sending individual messages, and saving drafts/templates.
2. **Zoho Campaigns API v1.1** is the existing free marketing account. The plan comparison says Developer API is available on Forever Free, but campaign sending is limited; scheduling, automated workflows, and webhooks are not included. Zoho Mail’s paid plan does not upgrade Campaigns. [Plan comparison](https://www.zoho.com/campaigns/comparison.html)
3. **Zoho Campaigns Email API v2** is a separate prepaid delivery product. Zoho says it is early access and enabled on request; an organization using Email API cannot also use the regular Zoho Campaigns product. Using both requires a separate organization. [Email API onboarding and pricing](https://help.zoho.com/portal/en/kb/campaigns/email-api/getting-started-guide/articles/getting-started-with-email-api)

Office can retain its own visual/HTML editor and booking backend. For regular Campaigns, Office supplies rendered HTML at the API’s `content_url`; for Email API, Office can send HTML/text inline or store the same content in Email API templates. Neither mode requires moving the editor or meeting-booking logic to Zoho. Zoho Mail must remain for mailbox work: Zoho’s current usage policy excludes promotional, bulk/mass, marketing, newsletter, automated, and transactional mail from Zoho Mail and directs marketing mail to Campaigns. [Mail usage policy](https://www.zoho.com/mail/help/usage-policy.html)

## Zoho Mail REST API

Authentication is OAuth 2.0. Use a **server-based** client for Office: request the least-privilege scopes, use the registered `client_id` and exact registered `redirect_uri`, request `access_type=offline` if refresh access is needed, and exchange the code on the server. Zoho documents one-hour access tokens and `Authorization: Zoho-oauthtoken …` for Mail API calls. Keep client secret and tokens server-side; do not call token or mailbox APIs from the browser. [Zoho Mail OAuth guide](https://www.zoho.com/mail/help/api/using-oauth-2.html)

### Campaigns footer and opt-out requirements

An imported Office HTML template must retain a Zoho Campaigns unsubscribe mechanism. For custom HTML, Zoho documents `$[LI:UNSUBSCRIBE]$` and `$[LI:ORG_OPTOUT]$`; removing the default footer is allowed only if an unsubscribe link remains in the content. Zoho’s review guidance says external unsubscribe links and multiple Zoho unsubscribe links are not accepted. A Campaigns recipient’s native unsubscribe can move the address into Do-Not-Mail, preventing future mail from the account. Therefore an Office-owned unsubscribe URL cannot replace the native Campaigns tag: Office should push its own opt-outs through the v1.1 unsubscribe/suppression API and poll provider opt-outs back. The Free comparison shows webhooks unavailable, so this reverse synchronization is polling-based rather than real-time. [Unsubscribe requirements](https://help.zoho.com/portal/en/kb/campaigns/deliverability-guide/reputation-management/articles/what-is-unsubscribes), [review FAQ](https://help.zoho.com/portal/en/kb/campaigns/faqs/campaign-review/articles/campaign-review-faq), [plan comparison](https://www.zoho.com/campaigns/comparison.html)

Forever Free includes the Developer API, Topics, merge tags, reports and the basic template editor, but not scheduled campaigns, automated workflows or webhooks. In the comparison table, Professional is the only plan explicitly marked as supporting email attachments; the free attachment entitlement is not established, so do not assume it. The free plan also retains the Zoho Campaigns logo in the footer; Zoho says the logo is removed on a paid plan. The Office integration described here does not use workflows, automatic sequences, schedule endpoints or scheduled actions. [Plan comparison](https://www.zoho.com/campaigns/comparison.html), [footer logo FAQ](https://help.zoho.com/portal/en/kb/campaigns/faqs/settings)

Zoho documents only `ZohoCampaigns.emailapi.ALL` for API-key scope and the header `Authorization: Zoho-zapikey <api_key>`. Generate/store the key server-side and never expose it in browser code or a public repository. [Authentication](https://www.zoho.com/campaigns/help/emailapi/authentication.html)

## Security and operational boundaries

- Use Zoho’s server-side OAuth authorization-code flow for Mail and Campaigns. The `redirect_uri` in the authorization and token exchange must match the URI registered in the API Console; exchange codes and refresh tokens on the backend. Keep client secrets, refresh tokens, OAuth tokens, and Email API keys in the server secret store. [Mail OAuth flow](https://www.zoho.com/mail/help/api/using-oauth-2.html), [server-based OAuth redirect rules](https://www.zoho.com/developer/oauth/web-server-apps/get-authorization-code.html)
- Restrict permissions to operations Office actually needs: Mail accounts/folders/messages READ and messages CREATE; Campaigns contacts READ/UPDATE, campaign CREATE/UPDATE/READ, plus contact CREATE only if Office must create custom fields or topics. Avoid DELETE/ALL OAuth scopes. Email API’s documented key scope is `emailapi.ALL`, which is broad and should be stored and used only by server-side code.
- Bind each connection to the account’s data center. Zoho documents region-specific Campaigns and Accounts hosts; do not derive an API or OAuth host from untrusted input. [Campaigns data centers](https://www.zoho.com/campaigns/help/developers/data-centers.html), [OAuth multi-DC](https://www.zoho.com/developer/oauth/multi-dc-support.html)
- A recipient-level unsubscribe must update Office suppression before any later export/send. Do not let a contact re-subscribe through ordinary list synchronization after a provider opt-out. Native Campaigns opt-out is account-wide Do-Not-Mail; the documented write API can add to it, while an account-wide registry read endpoint was not verified.
- Keep Meeting booking links on Office’s backend. They can be included in the HTML that Office authors; none of the verified mail/marketing APIs here replaces Office’s booking behavior.
