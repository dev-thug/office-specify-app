# 기업별 맞춤 메일 캠페인

캠페인은 여러 기업의 영업 활동을 묶는 작업 공간입니다. 기업마다 새 캠페인을
만들지 않아도 됩니다. 같은 캠페인 안에서 각 기업·담당자에게 다른 제목과 본문을
작성하고, 템플릿의 디자인·서명·미팅·수신 거부 버튼을 재사용합니다.

## 발신 설정

메일 계정 설정에서 활성 SMTP 마케팅 연결을 기본 영업 발신자로 지정합니다.
발신 별칭과 답장 주소도 이 연결에서 관리합니다. 캠페인 작성 중에는 SMTP
호스트·공용 메일함·채널을 반복 선택하지 않습니다. 사용할 수 있는 연결이 하나뿐인
워크스페이스는 그 연결을 사용하며, 여러 연결이 있으면 관리자가 기본값을 정해야 합니다.
권한이 없거나 연결이 중지된 기본값을 다른 연결로 몰래 바꾸지 않습니다.

캠페인을 만들 때 발신 연결을 고정합니다. 나중에 기본값을 바꾸어도 이미 만든
캠페인의 발신자는 바뀌지 않습니다. 연결이 중지되면 발송도 차단됩니다.
미팅 유형을 지정하면 해당 캠페인의 기본값으로 고정합니다. 지정하지 않았다면
메일 검토·동결 때 미팅 유형을 선택할 수 있으므로, 미팅 버튼 때문에 캠페인을
새로 만들 필요는 없습니다.

## 칸반 사용 순서

메인 메뉴의 **캠페인**에서 시작합니다. 담당자 관리는 **기업 → 담당자**,
승인 검토는 **캠페인 → 승인함**, 예약 유형 관리는 **미팅 → 미팅 유형**에서
접근합니다. 발신 계정과 에이전트·가져오기·운영 도구는 **설정**에 모여 있습니다.

1. 캠페인 이름·목표를 정하고 기업의 담당자와 이메일을 선택합니다. 한 캠페인은
   최대 200개 대상을 담으며, 보드가 일부 대상을 숨긴 채 보여주지는 않습니다.
2. **조사 완료:** 기업 상세에서 조사 결과·기사·인터뷰 등의 출처를 확인합니다.
   출처는 CRM 조사 자료와 노트에 보관합니다.
3. **초안 작성:** 카드를 열어 해당 기업에 맞는 제목과 본문을 작성합니다.
   템플릿을 선택할 때는 저장된 버전을 사용합니다. 에이전트도 MCP로 각각 다른
   초안을 만들 수 있습니다. 앱 자체가 외부 모델을 자동 호출해 글을 생성하지는 않습니다.
4. **검토:** 렌더링된 메일을 확인하고 기존 메시지 동결·승인 절차를 진행합니다.
   동결 전의 변수 예시 화면과 실제 수신자 값·링크가 들어간 동결 미리보기를 구분합니다.
   작성자와 별도의 사람 승인이 필요합니다. 칸을 옮기는 행위는 승인이 아닙니다.
5. **발송 대기:** 현재 초안의 정확한 동결본이 승인된 뒤 카드 오른쪽 손잡이를
   끌거나 이동 버튼으로 보냅니다. 서버가 다음 10분 단위 시각에 처리할 저장된 작업을 생성합니다.
   예를 들어 14:03에 넣으면 14:10 이후 처리 대상이 됩니다.
6. **전송됨:** SMTP 서버가 접수를 확인한 메시지를 표시합니다. 보드는 2초마다
   상태를 다시 읽습니다. 수신함 도착이나 실제 사람의 열람을 증명하는 상태는 아닙니다.
7. **확인 필요:** 실패·결과 불확실 등의 상태를 확인합니다. 결과가 불확실한 메일은
   중복 발송 방지를 위해 자동으로 다시 보내지 않습니다.

발송 시각이 되어도 승인 만료·자격증명 폐기·수신 거부·발신 연결 중지·발송 한도·
허용 시간 등의 기존 검사는 다시 실행됩니다. 따라서 다음 배치 시각은 발송 보장 시각이
아닙니다. 기존 Inbox나 MCP 개별 발송 경로로 들어가도 연결된 캠페인 메시지는
같은 수신자·발신자·현재 초안·배치 규칙을 따릅니다.

기존 공통 템플릿 일괄 발송 캠페인은 별도 일괄 발송 경로에서 계속 확인합니다.
기존 승인 내역과 동결된 메시지는 새 보드 형식으로 재해석하지 않습니다.

카드를 열면 검토를 마친 자료까지 포함한 출처, CRM 기업 요약과 조사 노트를 함께
볼 수 있습니다. 서식 이메일은 화면에서 편집하거나 **HTML 편집**으로 소스를
전환할 수 있습니다. 서버가 허용하는 인라인 글꼴·색상·여백·너비·테두리는 편집과
미리보기에서 유지하며, 스크립트·외부 리소스·숨김 CSS 등은 제거합니다. 동결 전의
샘플 미리보기는 승인 대상이 아니며, 동결된 수신자별 본문으로 검토해야 합니다.
전송된 카드에서 **후속 초안 작성**을 선택하면 별도의 새 초안을 만들며, 다시
동결·승인해야 발송할 수 있습니다.

## 에이전트 연결

1. `crm_search_companies` → `crm_get_company`로 기업과 기존 조사 자료를 읽고,
   `crm_search_contacts` → `crm_get_contact`로 담당자·이메일 ID를 확인합니다.
2. `research_add_evidence`와 `crm_create_note`로 실제 출처와 영업 가설을 기록합니다.
   기업 정보 변경은 기존 제안·사람 검토 절차를 따릅니다.
3. `sales_campaigns_list` / `sales_campaigns_create` / `sales_campaigns_get`으로
   기존 캠페인을 재사용하거나 만듭니다.
4. `sales_campaigns_add_target`에는 실제 조회 결과의 `company_id`, `contact_id`,
   `email_address_id`를 넣습니다. 이메일 문자열이나 회사 이름을 ID 대신 넣지 않습니다.
5. `sales_campaigns_create_message`로 각 대상에 다른 초안을 저장합니다.
   선택 사항인 `template_version_id`는 템플릿 컨테이너 ID와 다릅니다.
   `meeting.booking_url`과 `compliance.unsubscribe_url`은 서버가 생성하므로 직접 값을 넣지 않습니다.
6. `sales_campaigns_move_stage`는 `research`, `draft`, `review` 준비 상태만 바꿉니다.
   사람에게 정확한 미리보기와 승인 요청을 인계합니다.
7. 승인 후 최신 보드를 다시 읽고 `sales_campaigns_queue`에 현재 대상 버전,
   동결 메시지 ID와 정확한 해시를 넣습니다. `mail.submit_approved`와 현재 발송
   grant가 필요합니다. 동일 작업 재시도는 같은 idempotency key를 사용합니다.

도구 공개는 권한 부여가 아닙니다. 에이전트에는 필요한 `campaign.compose`,
`crm.read`, `mail.read`, `mail.compose`, `mail.submit_approved`와 해당 메일함 grant만
부여합니다. `mail.send`, `mail.approve`는 에이전트에게 제공하지 않습니다.
